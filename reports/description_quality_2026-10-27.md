# 描述事项生成诊断（protocol 5 / prompt 1.2）

索引：`runs/indexes/validmem-p5-20261027`（1225 条旧记忆 → 725 个条目，M1 开、M2 关）
数据：`data/validmem_v5`（188 条写入 / 288 个冲突对）
工具：`scripts/probe_description_quality.py`
日期：2026-10-27

四项检查在跑之前先定判定线，避免看到结果再调口径。

## 一、同事项收敛（决定事项层是否成立）

对 288 个 gold 冲突对，用生产同一条 `describe()` 给写入选条目，看是否与旧记忆的条目有交集；
同时把同渠道、非 gold 对象的随机旧记忆作为对照。

| | 冲突对 | 随机对照对 | 差值 |
|---|---|---|---|
| 全体 | **240/288 = 83.3%** | 50/26938 = **0.19%** | lift **438×** |
| world（537 条池） | 73/86 = 84.9% | 41/26864 = 0.15% | 555× |
| personal（池 1–3 条） | 167/202 = 82.7% | 9/74 = 12.2% | 6.8× |

- 记录级：world 的 22 条写入**全部**至少命中一个伙伴；30 条完全未命中的写入**全在 personal**。
- `partners_without_entry = 0`：没有旧记忆因为缺条目而不可达。
- 10/188 条写入（5.3%）返回**空选择**，全部 personal，这些记忆在事项层完全不可召回。

判定：**通过**（线为冲突对 ≥75%、对照 ≤15%）。事项层确实在区分"同一件事"与"两件不同的事"。

## 二、值泄漏（描述里是否写进了答案）

抽 120 个条目，问判定器"描述本身是否已包含该记忆给出的取值"。第一版判定器不可靠（抽查 10 条
至少 3 条误报，理由声称的片段根本不在描述里），改为**要求逐字引用描述中的连续片段并由程序校验**。

| 索引 | 判定器 | 泄漏率 |
|---|---|---|
| v7（prompt 1.1） | 无引用校验 | 16.7%（20/120） |
| p5（prompt 1.2） | 无引用校验 | 22.5%（27/120） |
| p5（prompt 1.2） | **逐字引用校验** | **16.0%（19/119，1 条无法核查）** |

人工复核 19 条：16 条确属泄漏（折扣「八折/七折」、日期「5月25日」「6月1日至8月31日」、
书名「Advanced Quantum Physics, 4th Edition」、药物「Drug D」），3 条为误报
（「完成状态」这类把事项当答案；以及整句引用绕过子串检查）。**修正后 13.4%**。

判定：**未通过**（线为 ≤10%）。提示词 1.2 相对 1.1 没有改善（16.7% → 16.0%，差异在噪声内）。

## 四、准入凭据是否成立

抽 40 条状态为 `new` 的新增，把它的描述、对照条目原文和声明的差异理由交给判定器，
问"这两条是不是同一事项"。

- 判为同一事项（即声明不成立、本应复用）：**7/40 = 17.5%**
- 人工复核这 7 条：5 条确属同一事项（如「夹克的原价」对「该物品的标准价格」、
  「新年游泳池会员的有效期」对「夏季游泳池会员的有效期」），2 条可争议

判定：**勉强通过**（线为 ≥80% 成立，实测 82.5%）。

## 五、48 个未命中冲突对的归因

| 归因 | 对数 | 占比 | 性质 |
|---|---|---|---|
| 旧条目把答案写进了描述（同一事项按值被拆开） | 14 | 29% | 目录侧 |
| 写入侧返回空选择 | 12 | 25% | 写入侧 |
| 写入侧没复用已存在的正确条目 | 22 | 46% | 写入侧 |

典型两种反向错误（都在"值 vs 必要实例限定"这条边界上）：

- `TC-A-0124` 旧条目「患者对**青霉素**的过敏史」——药物名是答案，写进描述后「阿莫西林」永远归不进去
- `TC-A-0057` 旧条目「患者**血压药物**的每日剂量」——把必要的实例限定（Lisinopril）也剥掉了，
  条目泛化到装不进任何具体药

## 六、结论

1. **事项层作为机制是成立的**：83.3% 对 0.19%，438 倍区分度，world 记录级 100%。
2. **"值不泄漏"没有实现**：13–16%，代码里零校验，只能靠提示词；它直接解释了 29% 的收敛失败。
3. **残差主要不在目录侧**：71% 的失败来自写入侧——5.3% 返回空选择，以及约半数明明存在正确条目
   却没选中/另提新事项。准入侧 17.5% 的"新增"其实应该复用，与这一条互相印证。
4. 说明 1.2 对 1.1 的修改没有改善泄漏，需要换成可判定的约束（例如要求生成时给出"被剥离的取值"
   并校验它确实不在描述里），而不是继续加形容词。

## 七、相对上一版（protocol 3 / prompt 1.1，`validmem-v7`）的对照

同一套测量跑在两份索引上，用的是同一批 188 条写入和 288 个冲突对。

| 口径 | v7（旧） | p5（当前） | 差 | 检验 |
|---|---|---|---|---|
| 冲突对级·全体 | 218/288 = 75.7% | 240/288 = **83.3%** | +7.6pt | McNemar 35 vs 13，p=0.0021 |
| 冲突对级·world | 55/86 = 64.0% | 73/86 = **84.9%** | +20.9pt | p=0.0001 |
| 冲突对级·personal | 163/202 = 80.7% | 167/202 = 82.7% | +2.0pt | p=0.56 |
| **写入级·全体** | 155/188 = 82.4% | 158/188 = **84.0%** | +1.6pt | +3/-0，p=0.25 |
| 写入级·world | 21/22 = 95.5% | 22/22 = 100% | +1 条 | — |
| 写入级·personal | 134/166 = 80.7% | 136/166 = 81.9% | +2 条 | — |
| 泄漏率 | 16.7% | 16.0% | ≈0 | 无引用校验口径 |

两点必须写进去的保留：

1. **对级提升被少数高连接写入放大**。20 个 world 翻转对只来自 **3 条写入**（TW-0013 / TW-0020 /
   TW-0006），每条各挂 6–7 个旧记忆。写入级看只有 +3 条（且 0 条回退），不显著。审稿人会问
   分析单元是写入还是对——应当两个都报。
2. **对照不是同条件重建**。v7 是历史上另一次构建，网关在 temperature 0 下非确定（两次构建目录
   文本仅重叠 46–50%），所以差异里混有构建随机性；同时 v7→p5 之间提示词与准入契约一起变了，
   提升是"整包"的，不能归给单个组件。

另外泄漏率几乎没变（16.7% → 16.0%），说明**这次提升不是靠修好值剥离换来的**；写入侧平均选中
条目数也只从 1.45 涨到 1.56，不是"选得更多"，而是少数 case 选对了。

## 八、这套测量的边界

- 对照是随机旧记忆，不是"同主体不同事项"的硬对照；personal 对照池只有 74 对，12.2% 不可靠。
- 泄漏与准入都用判定器，已加逐字引用约束，但"整句引用"仍能绕过一次。
- 单次构建。网关在 temperature 0 下非确定（两次构建目录文本仅重叠 46–50%），数字应视为一次抽样。
- 收敛不等于端到端召回：共享条目是必要条件，后续两阶段向量仍可能丢掉它。
