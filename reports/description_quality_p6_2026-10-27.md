# 描述事项生成·第二轮诊断（protocol 6 / prompt 1.3，事项—取值分离）

索引：`runs/indexes/validmem-p6-20261027`（1225 条旧记忆 → 691 个条目，M1 开、M2 关）
对照：`validmem-p5-20261027`（protocol 5 / prompt 1.2）、`validmem-v7`（protocol 3 / prompt 1.1）
日期：2026-10-27

## 一、实现的方案（来自 Claude 会话 #64）

对每条新增事项，模型必须同时输出：

- `value`：原文对该事项给出的回答（含必要的否定、状态、不确定信息），非空
- `description`：只含对象、待比较事项、识别实例所需限定，不含待比较答案

只有 `description` 进目录与描述向量；`value` 只用于生成分工与准入审计。
判据是**"换值不换事项"**：保持主体/事项/必要实例不变，只替换答案，`description` 应当不变。
同一次调用完成，不加第二次模型调用；不做字符串删除、不做词表剥离、不加二次语义审核。

## 二、实现核对（静态）

| 项 | 状态 |
|---|---|
| `PROMPT_VERSION` / `BUILD_PROTOCOL` | `1.3` / `6` |
| `value` 必填且非空 | `_new_items` 用 `nonempty_text` 校验，缺失即格式错误 |
| 只有 `description` 进目录 | 目录条目文本取自 `description`；`value` 仅落在 `admission.items` |
| "换值不换事项"写进提示 | 两版提示词均有该自查句与"不能写成'推荐A教材的情况'"的反例 |
| 首批/空目录同样遵守 | 提示词显式要求 |
| 单测 | 84 项通过（含新增 `test_value_separation.py`） |

## 三、统一口径的两个变更（重要）

1. **收敛度量改为运行时口径**。运行时用的是 `describe()` 解析后的 `descriptions`
   （选中项与"确认无差异"的复用项都会被替换成目录原文），只数 `selected_ids` 会把这类复用
   漏成"空选择"。上一轮报告的 **83.3% / 438×** 用的是旧口径，**不再可用**。
2. **三份目录统一用 prompt 1.3 的查询侧重新测量**，因此可相互比较；不能与 1.2 时代的数字混用。

## 四、四项检查

### 1. 值泄漏（方案的目标）

| 索引 | 判定器（逐字引用校验） | 机械口径 | 人工复核 |
|---|---|---|---|
| v7（1.1） | 16.7% | — | — |
| p5（1.2） | 16.0%（人工修正 13.4%） | — | — |
| **p6（1.3）** | **4.2%（5/120）** | 6/754 = **0.8%** | 抽 20 条：0 条含具体取值，3 条"断言了事实"（边界） |

包装式外壳（"…的情况/的更新状态"）没有变多，反而减少：p5 13.5% → p6 5.1%。
具体案例可以直接对照：p5 的「母婴用品八折优惠活动的折扣力度」在 p6 变成「母婴用品优惠活动的折扣」。

判定：**通过**（线为 ≤10%），且相对 16% 是四倍下降。

### 2. 同事项收敛（统一查询口径 1.3 + 运行时度量）

| 目录 | 冲突对级 | personal | world | 随机对照 | lift |
|---|---|---|---|---|---|
| v7（1.1） | 207/288 = 71.9% | 76.7% | 60.5% | 0.17% | 445× |
| p5（1.2） | 221/288 = **76.7%** | 76.2% | 77.9% | 0.19% | 403× |
| **p6（1.3）** | 220/288 = **76.4%** | 81.2% | 65.1% | 0.21% | 364× |

p6 相对 v7：+13 对，p=0.142（不显著）；相对 p5：−1 对（等价）。
p5 与 p6 的差别只是在两个渠道间互换（world 67→56，personal 154→164），净额为零，属构建噪声量级。

判定：**方案没有改变收敛**。区分力仍在（76% 对 0.2%，约 364 倍），但与上一版持平。

## 五、结论

1. **方案的目标达成了**：值泄漏从 16% 降到 4.2%（机械口径 0.8%，人工抽检 20 条无具体取值）。
2. **没有副作用到收敛上，但也没有加分**：76.4% 对 76.7%，在构建噪声范围内。
3. 上一轮报告的 83.3%/438× 是度量口径错误，已作废；正确口径下当前系统是 **76.4% 对 0.21%（约 364 倍）**。
4. 残余问题换位了：不再是"值写进描述"，而是**准入侧仍把 15% 的"新增"误判为不同事项**，
   以及 0.90 阈值下的目录近重复已到 9.7%。

## 六、边界

- 单次构建；网关 temperature 0 下仍非确定，p5 与 p6 的 ±1 对差异不可解释。
- 泄漏判定器仍有系统偏差：它只认"具体取值出现在描述里"，对"断言了事实但不含取值"
  （如「药物B的停用情况及原因」）偏宽；人工抽检 20 条里这类边界有 3 条。
- 收敛度量按文本回查条目，同一文本若对应多个条目会计入全部；当前目录文本唯一，不触发。
- 准入口径用判定器，40 条样本，人工只复核了 p5。
