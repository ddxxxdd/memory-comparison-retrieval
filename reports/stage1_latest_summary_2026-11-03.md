汇总日期：2026-11-03。基于已保存的逐查询结果独立复算，无新增推理或付费调用。

当前工作区最新完整主实验为 `validmem-v7-main-20261030`（我们的方法、BM25、Dense、Hybrid）；SparseCL 为 `validmem-v7-sparsecl-exploratory-20261031-retry1`。两次运行的输入哈希一致：1225 条旧记忆、181 条查询、301 个正冲突对，所有查询共享完整旧库。当前未发现更新的本地实验目录；检查时本机及已连接服务器未见相关实验进程。

## 统计口径

- R = 命中的金标冲突对数 / 301；P = 命中的金标冲突对数 / 返回候选总数。两者均按配对做 micro 汇总。
- 候选 F1 = 2PR/(P+R) = 2×命中数/(301+候选总数)。不是最终冲突分类 F1；当前各方法均未运行共同的下游冲突判定器。
- 完整找全率 = 找全该查询所有 gold 的查询数 / 181。
- 纯度相对于现有 gold；未在 gold 中的返回项未经人工核验，不能全部视为真实误报。

## 简单分析

1. **当前最明确的收益是候选压缩与召回的平衡。** 我们的方法命中 289/301，仅输出 411 个候选，候选 F1 为 81.18%。相对 Dense@10，召回高 4.65 个百分点、纯度高 55.12 个百分点、候选数减少 77.29%。与 Hybrid@20 同为 289 个命中，候选从 3620 降到 411，减少 88.65%。
2. **召回并非全面领先。** Dense@20 的召回为 97.01%，高于我们的方法 96.01%；完整找全率也为 99.45%，高于 96.69%。top-50 的 Dense/Hybrid/SparseCL 召回进一步提高，但纯度仅约 3.3%。top-k 下候选 F1 明显受输出预算影响，应与 R、P、候选数一起解释。
3. **候选少的代价是上游生成成本。** 我们的方法单条均值 26.88 秒，约为 Dense 的 25.97 倍；p50 约 21.89 倍。952 项全目录的描述选择消耗 3,182,818 token，占在线 LLM token 的 75.28%，是首要 token 优化点。生成假设/主体事项比较阶段累计 API 时间约 3287 秒，是耗时重点。返回 411 个候选之前，LLM 已处理 2807 个粗候选，不能将输出压缩等同于整个系统低成本。
4. **多目标样本影响 micro 优势。** 单条 TW-0013 有 29 个 gold，我们方法命中 26，Dense@10 命中 10；该条贡献 +16，而整体只多命中 14。去掉该条的敏感性诊断为 96.69% 对 97.43%，因此不能仅凭总召回声称普遍优于 Dense。
5. **SparseCL 本地迁移尚未显示额外召回收益。** 固定官方 Arguana alpha=0.18、使用英文预训练模型；在已报告预算点，其融合与同模型体系的 BGE cosine 对照召回一致。该观察只适用于当前迁移设置。
6. **优先做低成本对照。** 现有 Dense 排序按 cosine≥0.7 回放可得 295/301=98.01% 召回、21.53% 纯度、35.31% 候选 F1、平均 7.57 个候选；这是事后诊断，未单独计时。下一步适合比较“Dense 动态阈值 + 同一主体/事项筛选器”，并减少全目录在线输入。

当前数据为探索集，181 条全有正冲突，gold 的 `human_reviewed` 和 `fully_reviewed` 全为 false；尚无独立人工核验测试集及共同 final judge。因此可以支持“候选更集中、生成更贵更慢”，尚不能支持“端到端更省钱”或正式泛化结论。
